# 个人知识库管理系统

## 一句话目标

以 Obsidian 为当前载体，建立“项目、资产、资源、辅助、灵感、Skill”六框架知识系统，让资料能够持续进入、被验证、形成关系并沉淀为可复用成果。

## 成功标准

- 六类内容都有统一入口、模板和元数据规范。
- 新增正式笔记可以被自动校验，错误路径或错误字段不会假通过。
- 旧文档先生成透明的归属建议，未经确认不移动、不晋升。
- 资产与 Skill 有明确的候选、确认、复查和退役流程。
- 项目进展、下一步、关联资产和可复用方法可以从一个页面持续追踪。

## 当前状态

### 已完成

- 建立系统区、收件箱、六框架和归档入口。
- 建立六类正式笔记模板与统一元数据规范。
- 建立确定性结构校验器，覆盖重复键、字段类型、唯一主归属和错误仓库路径。
- 建立只读迁移审计器及输出防覆盖保护。
- 完成 51 篇根目录 Markdown 的首轮映射。
- 建立健康报告与待确认队列。
- 完成“输入—消化—业务输出—内容派生—反馈回写”双循环实施及验收基线；驾驶舱可由当前知识库确定性重现。

### 当前数据

- 根目录当前 Markdown：63 篇（不含系统 AGENTS.md；首轮 51 篇中已迁移 8 篇、仍留 43 篇，首轮后新增 20 篇）。
- 首轮迁移建议：项目 5、资产候选 8、资源 6、辅助 10、灵感 4、需人工复核 18。
- 已确认进入六框架的正式内容：共 12 篇（项目 1 篇、资产 8 篇、辅助 3 篇）。
- 首批资产候选已全部批准并完成；当前无高置信度 Skill 候选。

## 下一步

1. 导入并测试默认 Web Clipper 收件箱模板，完成首个真实输入闭环。
2. 人工处理“需人工复核”页面，优先确认旧 Index、AI短剧、AI账号运营和每日沉淀入口的定位。
3. 确认项目、资源、辅助和灵感类建议后分批迁移。
4. 逐篇补足已迁移资产的 `derived_from` 和 `source_refs`，完成资产来源追溯。
5. 从已稳定的辅助文档中识别可执行、可验证、可复用的 Skill 候选；经用户确认后再推进。

## 决策记录

- 第一阶段使用 Obsidian；可视化后台作为第二阶段独立建设。
- 每篇正式笔记只有一个主归属，跨框架使用 YAML 关系和 wikilink。
- 旧文档移动、改变主归属、晋升资产或 Skill，必须获得用户确认。
- `30-资源/raw` 保存原始来源，不允许审计工具覆盖。
- 分类器只输出可解释建议，弱分或并列统一进入人工复核。

## 风险与待确认

- 根目录仍有大量混合类型文档，尚未实际迁移。
- 旧文档迁移建议仍是开放工作，任何移动或唯一主归属调整继续等待用户确认。
- 已迁移资产的来源追溯尚未补齐；在 `derived_from` 和 `source_refs` 完整前，不将其视为来源链已完成。
- 旧 Index 与新六框架入口并存，需在迁移完成后统一导航关系。
- “终稿、报价、交付”只代表高价值候选，仍需确认是否确为当前有效版本。
- Skill 候选不足，不能仅凭“方法论”命名直接晋升，需验证输入、步骤、输出和失败边界。
