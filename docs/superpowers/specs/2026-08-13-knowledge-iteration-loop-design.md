# 个人知识库迭代闭环设计

日期：2026-08-13

状态：用户已确认设计，待书面审阅

适用知识库：`E:\李大谱的小脑瓜`

## 1. 设计目标

在现有“项目、资产、资源、辅助、灵感、Skill”六框架之上，建立可持续运行的知识迭代系统，使知识不止被存储，而是持续经历：

`输入 → 消化 → 连接项目 → 形成输出 → 获取反馈 → 更新知识 → 资产/Skill 候选`

系统优先服务真实业务结果；AI 短剧、口播和账号内容复用业务实践中的问题、判断、案例和方法，不另建一套脱离业务的内容生产系统。

## 2. 已确认的运行选择

- 运行模式：双循环运营型。
- 输出策略：双轨并行，业务结果为主，内容输出复用业务过程。
- Web Clipper：混合入口。
- 日消化投入：每天 10 分钟，最多处理 3 条。
- 周复盘投入：每周 30 分钟，只承诺一个业务关键输出和一个派生内容选题。

## 3. 总体架构

系统由两层循环构成。

### 3.1 日循环：控制输入质量

每天用 10 分钟，从收件箱选择价值最高的 3 条输入，依次完成：

1. 捕获：网页、文件、对话结论、会议信息或临时想法进入系统。
2. 筛选：判断是否与当前项目有关，或未来是否可能复用。
3. 提炼：提取事实、观点、方法和待验证假设，形成一句话结论。
4. 路由：确定唯一主归属；不确定时继续留在收件箱。
5. 连接：链接活跃项目、已有知识，或设置明确复查日期。

日循环不要求清空收件箱，也不以长摘要为完成标准。每天只完成最重要的 3 条，保证系统可以长期持续。

### 3.2 周循环：推动真实输出

每周用 30 分钟完成：

1. 复盘活跃项目的变化、阻塞、新证据和外部反馈。
2. 选择下周唯一业务关键输出，并写明验收标准。
3. 从该业务过程派生一个内容题目和素材来源。
4. 检查真实使用是否产生资产、综合页或 Skill 候选。
5. 将使用结果和反馈回写到项目及相关知识页面。

如果连续两周没有完成业务输出，应缩小输出范围，而不是增加整理时间。

## 4. 输入系统

### 4.1 输入来源

- Obsidian Web Clipper。
- 用户与 AI 的工作对话和确认结论。
- 本地 Markdown、Word、PDF、表格等文件。
- 项目过程、客户反馈和交付结果。
- 临时想法、观察和机会线索。

### 4.2 Web Clipper 混合入口

#### 默认入口：`01-收件箱`

以下内容默认进入收件箱：

- 普通网页；
- 临时想法；
- 对话片段；
- 来源不明确的内容；
- 尚不能确定唯一主归属的材料。

#### 可信模板入口：`30-资源/raw`

只有同时满足下列条件的网页，才允许通过已配置模板进入 raw：

- 来源属于事先认可的官方网站、行业报告、固定媒体或研究网站；
- 需要保留原文作为证据；
- Clipper 模板保留 URL、标题、抓取日期和来源机构；
- 抓取内容不包含不应保存的账号秘密、令牌或敏感信息。

`30-资源/raw` 是只读证据层。后续消化必须另建资源或其他框架笔记，不覆盖原始抓取文件。

### 4.3 收件箱积压规则

- 收件箱超过 30 条时触发积压提醒。
- 优先处理与活跃项目相关的内容，其次处理有明确复用价值的内容。
- 最旧且无项目连接、无明确复用场景的内容优先归档。
- 未完成消化标准的内容不得强行进入六框架。

## 5. 消化系统

### 5.1 五个判断

每条输入依次回答：

1. 值不值得保留？
2. 它主要属于事实、观点、方法还是想法？
3. 可信度是 `confirmed`、`inferred` 还是 `unverified`？
4. 唯一主归属是什么？
5. 下一步是行动、连接项目、设置复查日，还是归档？

### 5.2 最低完成标准

一条输入只有同时具备以下信息，才算“已消化”：

- 一句话结论；
- 明确可信度；
- 唯一主归属；
- 至少一个项目/知识关联，或一个明确复查日期。

未达到最低标准的输入继续留在收件箱。

### 5.3 状态流转

输入状态按以下路径演化：

`captured → triaged → digested → connected → used → reviewed`

- `captured`：已捕获，尚未判断。
- `triaged`：已判断价值和优先级。
- `digested`：完成最低消化标准。
- `connected`：已链接项目、行动或复查日。
- `used`：已在业务决策、交付或内容生产中真实使用。
- `reviewed`：使用结果和反馈已回写。

重复或无价值输入可以在 `triaged` 后归档。未经真实使用的知识不得直接晋升 Skill。

## 6. 六框架路由规则

- 项目：有明确目标、推进状态、下一步和验证过程。
- 资产：已加工、已确认、具明确复用价值的成果。
- 资源：外部来源、证据、报告、数据和拆解。
- 辅助：模板、提示词、清单、SOP 和工具说明。
- 灵感：尚未验证的想法、机会、假设和连接。
- Skill：经过实际验证、可重复执行并具有验收标准的方法包。

一篇正式笔记只能有一个主归属。跨框架关系使用 YAML 字段与 Obsidian wikilink 表达。

## 7. 输出系统

### 7.1 业务输出主线

每周只选择一个对当前业务最关键的输出，例如：

- 客户诊断；
- 经营驾驶舱方案；
- 项目决策；
- 报价或合作方案；
- 交付文档；
- 访谈提纲与结果；
- 验收或复盘报告。

每个业务输出必须写明：服务哪个项目、解决什么问题、调用了哪些知识、验收标准是什么、实际结果如何。

### 7.2 内容派生轨

内容输出直接复用真实业务过程，包括：

- 客户普遍痛点；
- 常见错误认知；
- 方案取舍；
- 实施失败和教训；
- 可公开的方法与案例；
- 真实反馈中的问题和反对意见。

派生内容可以转换为口播、短剧、案例、图文或直播提纲。转换前必须脱敏，区分事实、判断和推测；不得泄露客户隐私或未经授权的业务信息。

### 7.3 每周固定产物

- 一张本周项目变化摘要；
- 一个下周业务关键输出及验收标准；
- 一个业务派生内容题目及素材来源；
- 必要时生成资产、综合页或 Skill 候选并进入待确认队列。

## 8. 反馈与知识升级

### 8.1 反馈来源

- 客户是否采用方案；
- 是否成交、交付或通过验收；
- 经营指标和项目结果；
- 客户、合作方和团队反馈；
- 内容完播、互动、咨询与真实问题；
- 新来源对旧结论的支持或反驳。

### 8.2 回写规则

- 项目：更新进度、阻塞、决策、结果和下一步。
- 资产：真实使用有效后升级版本；被推翻或失效时标记 `deprecated`，保留历史记录。
- 灵感：记录进入项目、被采用或被否决的结果和原因。
- Skill：只有步骤经过实际验证，并具输入、输出、验收和失败边界时，才成为候选。
- 综合页：跨多个来源形成稳定判断时提出候选；新来源加入后更新版本。

移动旧文件、改变唯一主归属、晋升资产、综合页或 Skill，必须由用户确认。

## 9. 知识迭代驾驶舱

首页看板只回答四个问题：

1. 今天处理哪 3 条输入？
2. 本周唯一业务输出是什么？
3. 哪里出现积压、到期或阻塞？
4. 哪些知识需要确认、复查或升级？

看板包含：

- 今日 Top 3；
- 本周唯一业务输出及验收标准；
- 本周内容派生选题；
- 待确认事项；
- 活跃项目状态、阻塞和下一步；
- 收件箱积压、到期复查和孤立知识提醒。

## 10. 运行指标

系统只跟踪六个指标：

1. 输入积压：收件箱当前数量，超过 30 条触发清理。
2. 消化完成率：本周已消化数量 ÷ 本周选中处理数量。
3. 项目连接率：已消化知识中，连接活跃项目或复查日的比例。
4. 业务输出兑现：每周唯一业务输出是否完成并通过验收。
5. 知识复用次数：资产、资源或辅助被真实项目调用的次数。
6. 反馈回写率：已使用输出中，记录了结果和反馈的比例。

这些指标用于发现系统是否产生业务价值，不用于追求笔记数量。

## 11. 自动化与权限边界

### 11.1 AI 可自动执行

- 新建收件箱笔记和正式笔记；
- 补充元数据；
- 去重、建立链接和生成归属建议；
- 生成每日 Top 3 建议和每周复盘草稿；
- 提醒积压、到期复查和无下一步的项目；
- 更新 Index、日志、统计和健康报告；
- 生成重复、冲突、孤立页及晋升候选建议。

### 11.2 必须人工确认

- 移动旧文件；
- 改变唯一主归属；
- 晋升资产、综合页或 Skill；
- 删除或覆盖原始来源；
- 对外发布内容；
- 客户承诺、报价定稿、合同签署和重大业务判断。

## 12. 异常与降级处理

- 当天没有时间：只捕获，不强行消化；下一天仍只处理 Top 3。
- 收件箱超过 30 条：优先处理项目相关内容，并归档最旧的无连接低价值输入。
- 连续两周未完成业务输出：缩小输出范围，不增加知识整理时长。
- 知识超过复查日：标记待复核，不自动删除或覆盖旧结论。
- 新证据推翻旧结论：新版本说明变化，旧版本保留并标记失效。
- 来源冲突：记录冲突双方、当前裁决依据和仍待验证的部分。
- 自动分类不确定：保留在收件箱，不做高置信归属。

## 13. 实施范围

第一阶段只在现有 Obsidian 系统内实施：

- 知识迭代驾驶舱；
- 收件箱输入模板与 Web Clipper 模板约定；
- 日消化清单；
- 周复盘模板；
- 输入状态字段与指标字段；
- 健康报告和待确认队列扩展；
- 相关校验与测试。

第一阶段不建设独立后台、不接入向量数据库、不自动发布内容、不自动晋升资产或 Skill。

## 14. 验收标准

- 普通 Clipper 输入可进入收件箱，可信模板输入可进入 raw，且 raw 不被覆盖。
- 每条已消化输入均满足最低完成标准。
- 首页可以看到今日 Top 3、本周业务输出、内容派生、待确认和系统健康。
- 周复盘能够产生规定的四项固定产物。
- 反馈能回写到项目，并能形成受控的资产/综合页/Skill 候选。
- 六项指标可以由知识库现有数据计算或明确标记暂不可计算。
- 所有正式知识通过结构校验。
- 用户确认边界与敏感信息边界保持有效。
