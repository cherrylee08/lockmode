# 原始来源目录（raw/）摄入规范

## 核心原则

此目录仅用于**追加保存原始来源**，视为**只读**：
- 不得覆盖、改写或用加工内容替代原件
- 原始来源的更正、失效说明、解读和待核实项必须记录在相应的资源笔记中，而不是修改原始文件
- 允许删除明显错误/重复的文件，但保留删除记录（在资源笔记中说明）

## 什么可以放进 raw/

| 类型 | 示例 | 处理方式 |
|---|---|---|
| 网页文章 | 公众号文章、知乎回答、博客 | 保存为 Markdown 或 PDF |
| 报告/白皮书 | 行业报告、政策文件、论文 | 保存为 PDF（保留原始排版） |
| 视频拆解 | 抖音/小红书/视频号拆解稿 | 保存为 Markdown（含时间戳） |
| 会议/访谈记录 | 会议纪要、客户访谈录音转文字 | 保存为 Markdown 或文本 |
| 数据/表格 | 原始 Excel、CSV、截图 | 保存为原始格式 + 备注说明 |
| 聊天记录 | 关键决策的微信/飞书对话 | 保存为截图或文本（脱敏后） |
| 邮件/通知 | 重要邮件、系统通知 | 保存为文本或截图 |

**禁止放入**：
- 加工后的分析、结论或综合页（应放入对应框架）
- 临时草稿、缓存文件、下载依赖
- 未脱敏的敏感信息（客户隐私、密钥、密码）
- 非文本类大文件（视频原片、大型数据集）—— 可放链接/网盘引用

## 文件命名规则

```
YYYY-MM-DD_来源类型_简要描述_作者或来源[可选].ext
```

示例：
- `2026-08-10_文章_AI短剧合规指南_36氪.md`
- `2026-08-11_报告_2024中国SaaS市场白皮书_艾瑞.pdf`
- `2026-08-12_视频_抖音爆款结构拆解_李一舟_片段.md`
- `2026-08-13_会议_小淀镇企业调研_访谈记录_王总.md`

**规则**：
1. 日期在前：ISO 格式 `YYYY-MM-DD`，表示获取/摄入日期（不是原文发布日期）
2. 来源类型在后：使用统一类型标签（`文章`、`报告`、`视频`、`会议`、`数据`、`邮件`、`聊天记录`）
3. 简要描述：5-15 字，能一眼识别内容，不含特殊字符
4. 作者或来源：可选，知名来源建议保留（如 `36氪`、`艾瑞`、`王总`）
5. 扩展名：`.md`（文本）、`.pdf`（原文）、`.txt`（纯文本）、`.csv`（数据）

## 来源追踪格式

每份原始来源必须包含来源信息。如果是 Markdown 文件，在文件头部添加 YAML frontmatter：

```yaml
---
source_url: "https://..."          # 原始 URL（如有）
source_type: "文章"                # 来源类型
author: "作者名"                   # 作者/机构
published: "2026-08-10"            # 原文发布日期（如已知）
ingested: "2026-08-13"             # 摄入日期
credibility: "medium"              # 信任度：high / medium / low / unknown
---
```

如果是 PDF 或其他非 Markdown 文件，来源信息记录在对应的资源笔记中（`30-资源/` 下的正式笔记），通过 `source_refs` 链接回本文件。

### 信任度定义

- `high`：一手来源、官方文件、已验证的数据、专家访谈
- `medium`：行业媒体、分析报告、有出处的引用
- `low`：社交媒体观点、匿名爆料、未经核实的传闻
- `unknown`：来源不明或无法验证

## Web Clipper 接入方式

### 推荐工具：Obsidian Web Clipper（浏览器插件）

1. **安装**：Chrome/Edge 安装 Obsidian Web Clipper
2. **配置**：
   - 默认保存路径：`30-资源/raw/`
   - 模板选择：使用本文档的 YAML frontmatter 模板
   - 文件名格式：`{date:YYYY-MM-DD}_文章_{title}_{site-name}`
3. **使用**：
   - 遇到有价值的网页文章，点击 Web Clipper → 保存到 `raw/`
   - 会自动抓取正文、URL、标题，生成 Markdown
   - 手动补充 `credibility` 和 `author`

### 替代方案：手动保存

- **Markdown 保存**：浏览器 → 打印 → 保存为 PDF，或用 `readability` 工具提取正文
- **PDF 保存**：直接下载原文件，放入 `raw/`
- **视频/音频**：使用飞书妙记/通义听悟转文字，保存为 Markdown 放入 `raw/`

## LLM 消化流程（raw → 资源笔记）

原始来源**不能直接使用**。必须经过以下消化流程，转化为正式资源笔记：

```
raw/ 原始文件 → 资源笔记（30-资源/） → 灵感/项目/资产（按需晋升）
```

### 消化步骤

1. **读取原始来源**：AI 读取 raw/ 中的文件，提取关键事实、观点、证据和待验证项
2. **创建资源笔记**：在 `30-资源/` 下创建正式资源笔记，使用资源模板
   - `source_refs` 必须包含 raw/ 文件的相对路径（如 `raw/2026-08-10_文章_xxx.md`）
   - `source_url` 填入原始 URL
   - `credibility` 继承 raw/ 中的标记，可在消化后调整
3. **写入来源记录**：在资源笔记中记录：
   - 原始来源的摘要（3-5 句）
   - 关键事实（用 bullet 列出，标注置信度）
   - 与现有知识的关系（链接到已有笔记）
   - 待核实项（如果有）
4. **原始文件保持不动**：raw/ 中的文件不移动、不改写、不删除（除非明显重复或错误）
5. **索引更新**：在 `30-资源/Index.md` 中记录新资源笔记

### 消化标准（资源笔记 vs raw/ 的区别）

| 维度 | raw/ 原始文件 | 30-资源/ 资源笔记 |
|---|---|---|
| 内容 | 原文/原始记录 | 结构化摘要、事实提取、个人批注 |
| 格式 | 原文格式 | 统一模板（frontmatter + 固定章节） |
| 链接 | 无 | 有（链接到相关笔记、项目、灵感） |
| 置信度 | 原始标记 | 消化后可调整，加入个人判断 |
| 可修改 | 否（只读） | 是（可更新、补充、修正） |
| 生命周期 | 永久存档 | 可 review、可 deprecate |

## 修正与失效处理

如果原始来源被证明错误、过时或虚假：

1. **不修改 raw/ 文件**：保持原始记录，作为"当时看到的是什么"的存档
2. **在资源笔记中标注**：在对应资源笔记中加入 `## 修正与更新` 章节，说明：
   - 原始来源的问题（错在哪里、何时发现）
   - 正确信息来源（链接到新的资源笔记）
   - 对已有知识的影响（哪些笔记的结论需要修正）
3. **更新 frontmatter**：将 `status` 改为 `deprecated` 或 `superseded`，并添加 `superseded_by` 链接
4. **级联修正**：如果该资源已被综合页或资产引用，同步更新综合页/资产，标注修正依据

## 示例工作流

### 示例：摄入一篇公众号文章

1. 用户看到一篇《2024 中国 AI 短剧市场报告》
2. 使用 Obsidian Web Clipper 保存到 `raw/2026-08-13_报告_2024中国AI短剧市场报告_量子位.md`
3. 用户或 AI 执行"摄取这份资料"：
   - AI 读取 raw 文件，提取关键数据（市场规模、增速、头部玩家）
   - AI 在 `30-资源/` 创建 `KB-20260813-001 2024中国AI短剧市场报告.md`
   - `source_refs: ["raw/2026-08-13_报告_2024中国AI短剧市场报告_量子位.md"]`
   - 记录关键事实、待核实项（如"数据是否包含海外市场？"）
   - 链接到已有项目 `[[AI短剧 Index]]` 或灵感 `[[短剧合规灵感]]`
4. 更新 `30-资源/Index.md`

## 目录结构建议

```
30-资源/
├── raw/                    # 原始来源（只读）
│   ├── README.md           # 本规范
│   ├── 2026-08-10_文章_...  # 按日期+类型命名的原始文件
│   ├── 2026-08-11_报告_...
│   └── ...
├── Index.md                # 资源索引
├── KB-20260810-001_...md   # 已消化的资源笔记
└── ...
```
