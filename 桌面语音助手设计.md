# Voice Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Windows Voice Core that hears the local wake phrase “逗比”, shows an audio-reactive particle orb, inherits the current desktop context, launches or resumes official Codex Voice, enforces confirmation rules, and records an auditable task result.

**Architecture:** A Tauri 2 desktop shell owns the tray, overlay windows, Windows integration, audio capture, wake-word engine, orchestration state machine, SQLite audit store, and Codex desktop bridge. A React/TypeScript renderer owns the particle visualization, transcript/status presentation, and user controls. Voice and Agent integrations sit behind Rust traits so the official desktop bridge can later be replaced without rewriting the workbench.

**Tech Stack:** Windows 11; Tauri 2; Rust 1.77.2 or newer; React 19; TypeScript 5; Vite 7; Three.js; Vitest; Playwright; Cargo test; SQLite via rusqlite; Windows APIs via the `windows` crate; local keyword spotting through sherpa-onnx C API and a Chinese/English open-vocabulary KWS model.

## Global Constraints

- M1 supports Windows and Codex only; WorkBuddy, the full dashboard, AI short-drama workflow, and content operations remain out of scope.
- The phrase “逗比” is recognized locally; pre-wake audio is neither uploaded nor persisted.
- Target latency is approximately 1 second to visible orb and approximately 2 seconds to responding state on the reference machine.
- Screen capture starts only after wake or during an explicitly active session.
- Confirmation mode is the default.
- Direct mode never bypasses confirmation for deletion, payment, external sending, public publishing, or permission expansion.
- The app must not depend on undocumented Codex internals or bypass product permissions.
- Every task state change and direct action must be auditable.
- Keep native modules focused; no Rust source file should exceed 300 lines without a documented split.

- [ ] **Step 4: Implement the state machine with effects instead of side effects**

```rust
pub fn apply(&mut self, event: VoiceEvent) -> Result<Vec<Effect>, TransitionError> {
    match (&self.session.voice_state, event) {
        (VoiceState::Idle, VoiceEvent::WakeDetected) => {
            self.session.voice_state = VoiceState::CenteredListening;
            Ok(vec![Effect::ShowCenteredOverlay, Effect::CaptureContext, Effect::StartVoice])
        }
        (_, VoiceEvent::ActionProposed(action)) => {
            self.session.task_state =
                if self.session.mode == Mode::Direct && action.risk == RiskClass::Normal {
                    TaskState::Running
                } else {
                    TaskState::AwaitingConfirmation
                };
            Ok(vec![Effect::PersistState])
        }
        (_, VoiceEvent::Confirmed) if self.session.task_state == TaskState::AwaitingConfirmation => {
            self.session.task_state = TaskState::Running;
            Ok(vec![Effect::StartAgentTask, Effect::PersistState])
        }
        _ => Err(TransitionError::InvalidTransition),
    }
}
```

## Implementation Notes

- Use the official Tauri 2 global shortcut and tray APIs. The global shortcut plugin requires Rust 1.77.2 or newer: https://v2.tauri.app/plugin/global-shortcut/
- Use sherpa-onnx open-vocabulary keyword spotting so “逗比” can be configured without training a dedicated model: https://k2-fsa.github.io/sherpa/onnx/kws/index.html
- Use sherpa-onnx through its documented C/Rust-compatible API boundary: https://k2-fsa.github.io/sherpa/onnx/c-api/html/keyword_spotting.html
- Use Three.js `BufferGeometry` and `Points` for one GPU-backed point cloud rather than thousands of DOM elements: https://threejs.org/docs/pages/BufferGeometry.html and https://threejs.org/docs/pages/Points.html
- Treat the Codex desktop bridge as best-effort desktop coordination. The public product documentation does not establish an embeddable Codex Voice API.
