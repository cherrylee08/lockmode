# 元数据规范

以下 YAML 是机器可读词汇表，用于约定字段与稳定枚举；每个 Markdown 页面仍使用普通 frontmatter，而不是直接把此文件当作页面数据。

```yaml
required_common:
  - id
  - title
  - type
  - status
  - created
  - updated
  - owner
  - confidence
  - source_refs
  - related
  - review_date
types: [project, asset, resource, helper, inspiration, skill]
confidence: [confirmed, inferred, unverified]
knowledge_stage: [captured, triaged, digested, connected, used, reviewed]
feedback_status: [not_applicable, pending, recorded]
iteration_fields: [captured_at, capture_channel, summary, suggested_type, used_in, feedback_status, last_used, use_count]
project_status: [planning, active, waiting, blocked, completed, paused, archived]
inspiration_status: [captured, validating, in_project, adopted, rejected]
skill_status: [draft, validating, stable, deprecated]
```

## 公共字段

- `id`、`title`：稳定身份与标题。
- `type`：唯一主归属，只能是六类枚举之一。
- `status`、`created`、`updated`、`review_date`：生命周期与复查信息。
- `owner`：责任人。
- `confidence`：`confirmed` 为用户确认或直接证据，`inferred` 为需注明依据的 AI 推断，`unverified` 为不可直接作为对外结论的待核实信息。
- `source_refs`、`related`：来源与跨框架关系，使用列表。
- `captured` / `triaged` 阶段允许字段不完整；进入 `digested`、`connected`、`used` 或 `reviewed` 后，必须填写非空 `summary`、有效 `confidence`、一个有效的 `suggested_type`，并提供非空 `related` 或 `review_date`。
- `knowledge_stage`、`feedback_status` 和 `iteration_fields`：一旦填写，必须使用上述枚举和列表格式。处于 `used` 或 `reviewed` 的知识必须填写非空 `used_in`；`reviewed` 必须使用 `feedback_status: recorded`。

收件箱笔记在早期阶段可以暂时字段不完整；只有正式进入六框架的笔记必须具备全部公共字段。
