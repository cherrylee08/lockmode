# 知识库操作手册

## 系统边界

本系统采用“原始来源、LLM 维护的 Wiki、约束 Agent 的 Schema”三层分离。Obsidian Markdown/YAML 是唯一数据源；第一阶段不建设独立后台、不引入向量数据库，也不批量移动既有文件。

## 六类定义

- **项目（project）**：承载有明确目标、进度、下一步和验证过程的工作；完成后仍留在项目框架，成果可经确认晋升为资产，稳定方法可经确认晋升为 Skill。
- **资产（asset）**：用户已加工、确认且具复用价值的成果，例如报价方案、脚本终稿、客户调研档案、交付模板、对外方案、确认案例，以及**跨来源综合页**（见下方 Synthesis 机制）；必须有版本、确认人和来源项目。综合页是资产的子类型，asset_type 为 `synthesis`。
- **资源（resource）**：文章、报告、视频拆解、网页、课程笔记、原始数据、会议和访谈原始材料等外部输入与证据；必须保留来源信息，不直接作为已确认结论。
- **辅助（helper）**：模板、检查清单、提示词、SOP 和工具说明等执行支撑材料；不保存 Agent 运行日志或系统配置，也不自动参与成果晋升。
- **灵感（inspiration）**：尚未验证的想法、机会、假设和连接；进入项目或放弃后保留原始笔记与决策依据。
- **Skill（skill）**：已经验证、可被人或 AI 重复执行并产生稳定结果的方法包；至少包含触发条件、范围、输入、步骤、输出、验收标准、验证记录和失败/边界说明。

## 知识生产链

常见演化路径是：`资源（外部输入） → 灵感（待验证想法） → 项目（推进验证） → 资产（确认成果） → Skill（稳定方法）`。这不是强制流水线：资源可直接支持项目，灵感可长期保留，项目可产生多个资产和 Skill，资产与 Skill 都要保留来源关系；辅助横向支持所有阶段。

## Synthesis 综合页机制

### 定义

综合页（Synthesis）是一种特殊资产，用于**将分散在多篇笔记中的观察、结论或证据整合为单一、可复用的认知单元**。它不是简单的汇总，而是跨来源的再分析——包含比较、取舍、模式提取和明确判断。

### 何时创建

满足以下任一条件时，应提出创建综合页：

1. **跨来源方法论**：同一主题下有 3+ 篇来源笔记，各自结论存在关联、冲突或互补，需要一篇统一视角的梳理（例如"天津 SaaS 创业政策汇总"整合了 5 篇政府文件）。
2. **查询产物归档**：一次高质量查询产生了超越临时问答的结论，且该结论未来会被反复引用（例如"AI 短剧合规审查清单"来自 8 次项目讨论）。
3. **模式提取**：从多个项目/资源中识别出可复用的模式、框架或禁忌清单（例如"ToB 客户调研访谈框架"提炼自 3 个客户项目的经验教训）。
4. **冲突裁决**：不同来源对同一问题给出矛盾结论，需要显式裁决并说明依据（例如"豆包 vs 可灵视频生成对比结论"）。

### 创建规则

- **必须由用户确认**：AI 只提出候选、拟标题和摘要，写入待确认队列；用户批准后才新建页面。
- **归属唯一主类型**：综合页的主类型为 `asset`，`asset_type` 为 `synthesis`。
- **来源强制追溯**：`derived_from` 必须列出所有被综合的笔记 ID/标题；`source_refs` 列出原始外部来源（如有）。
- **置信度标记**：综合页中每条结论必须标注 `confirmed`/`inferred`/`unverified`；跨来源冲突处必须显式记录冲突点和裁决依据。
- **版本化**：综合页有版本号（从 v1.0 开始），新来源加入或结论更新时迭代版本，旧版本保留在版本记录中。
- **有失效期**：`review_date` 默认 30 天，因为综合结论最容易因新来源而过时。

### 元数据规范

综合页使用资产模板，额外约束如下：

```yaml
type: asset
asset_type: synthesis
confidence: confirmed # 综合页整体为 confirmed，但内部段落可分别标记
derived_from: ["KB-20260807-001 小淀镇调研", "KB-20260808-002 北辰区政策"] # 被综合的笔记
source_refs: ["https://...", "https://..."] # 原始外部来源（如有）
review_date: {{date+30d:YYYY-MM-DD}}
version: "v1.0"
approved_by: "李大谱"
```

### 页面结构

1. **综合问题**：一句话说明这篇综合页回答什么核心问题。
2. **来源图谱**：列出被综合的全部笔记，用 `[[笔记名]]` 链接，标注每篇贡献的核心信息。
3. **综合结论**：按主题分组，每组内给出整合后的判断，标注置信度。冲突点单独设立"冲突与裁决"小节。
4. **可复用输出**：明确这篇综合页可直接用于什么场景（如"放入项目启动 check list"、"作为客户沟通话术"）。
5. **版本记录**：记录版本迭代原因。
6. **待填补缺口**：如果综合过程中发现数据缺口、未验证假设或需要补充的来源，显式列出。

### 知识生产链中的位置

综合页在知识生产链中处于**高阶资产**位置：

`资源 → 项目 → 资产（含综合页） → Skill`

一篇综合页可以被进一步晋升：如果其方法论被验证 3+ 次且步骤可复现，可提出作为 Skill 候选；如果其结论被新来源推翻，应降级为 `status: deprecated` 并在健康报告中标记。

### 在 Index 中的呈现

综合页在对应领域的 `Index.md` 中单独设立"综合页"小节，按主题分组。不与普通资产混排，便于快速找到跨来源结论。

## AI 与用户权限

AI 可自动新建笔记、补充元数据、更新索引和日志、查重与建立链接、生成归属建议、更新项目摘要与健康报告。用户必须确认移动既有文件、改变唯一主归属、晋升资产和晋升 Skill。原始来源位于 `30-资源/raw/`，只读且不可由 AI 覆盖或改写。

## 操作流程

### 摄取

1. **保存原始来源**：新增资料（文章、报告、视频拆解、会议记录等）首先保存到 `30-资源/raw/`，按 `YYYY-MM-DD_类型_描述_来源.ext` 命名，并添加来源 YAML（见 [[30-资源/raw/README]]）。raw/ 只读，不可由 AI 改写。
2. **消化为资源笔记**：读取 raw/ 中的原始文件，提取关键事实、观点、证据和待验证项，在 `30-资源/` 下创建正式资源笔记（使用资源模板）。`source_refs` 必须链接回 raw/ 原始文件。
3. **查重与归属**：查询全局和框架 Index，检查重复与冲突，提出唯一主归属建议（是否同时关联项目、灵感或资产）。
4. **更新索引与日志**：新建或更新相关 Wiki 页面、相关 Index 和 `log.md`。一个来源只保留一份主来源；与旧结论冲突时显式记录，不静默覆盖。
5. **确认边界**：涉及移动、改归属或晋升时，写入待确认队列并等待确认。

### 查询与回写

1. 先读 `00-系统/index.md` 和对应框架 Index，再读相关页面和来源引用。
2. 回答时区分 `confirmed`、`inferred` 和 `unverified`。
3. 查询产生长期价值的比较、分析、方案或连接时提出回写建议。**如果该结论跨多个来源且具长期复用价值，优先回写为综合页（Synthesis）**。
4. 用户同意回写后，更新笔记、索引、关系和日志。

### 资产候选

仅当成果完整、用户确认、有明确复用场景、并具版本和来源关系时，才可成为资产。AI 只提出候选并写入待确认队列；批准前不移动文件或改变主归属。

### Skill 候选

仅当触发条件、输入输出、可执行步骤、验收标准和至少一次验证记录齐全时，才可成为 Skill。AI 只提出候选并写入待确认队列；批准前不移动文件或改变主归属。

### 每周轻巡检

检查收件箱积压、到期复查、没有下一步的进行中项目、待确认队列和长期未处理的灵感。

### 每月深巡检

检查页面矛盾、被新来源取代的旧结论、孤立页与缺少入链页面、缺少独立页面的重要概念、缺少来源或可信度的结论、重复页与版本漂移、资产/Skill 候选，以及可用新来源填补的数据缺口。

**执行语义巡检脚本**：

```powershell
& 'C:\Users\lee\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' scripts/kb_lint.py .
```

语义巡检输出 `WARNING` 或 `ERROR` 级别结果，按 `LEVEL<TAB>CODE<TAB>PATH<TAB>MESSAGE` 格式输出。重点关注：
- `ORPHANED_NOTE`：孤立笔记（无入链/出链）
- `BROKEN_LINK`：断链（[[...]] 指向不存在的文件）
- `EXPIRED_REVIEW`：review_date 过期
- `CONFIRMED_NO_SOURCE`：confirmed 结论缺少来源支撑
- `MISSING_DERIVED_FROM`：asset/skill 缺少来源追溯

巡检结果写入 [[00-系统/健康报告]]，按优先级分类并给出行动建议。

### 基础结构校验

校验正式六框架笔记的必填字段、唯一主归属、可信度和重复 ID；收件箱、原始来源和框架 `Index.md` 不作为正式笔记校验。执行以下命令：

```powershell
& 'C:\Users\lee\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' scripts/kb_validate.py .
```

没有 `ERROR` 时命令返回 `0`；存在 `ERROR` 时返回 `1`。每条结果使用 `LEVEL<TAB>CODE<TAB>PATH<TAB>MESSAGE` 格式输出。

## 节奏

每周执行一次“每周轻巡检”，每月执行一次“每月深巡检”。任何正式知识变更都同步更新相应 Index 和 `00-系统/log.md`。

## 用户命令

1. "摄取这份资料。"
2. "查询并回写这个问题的长期结论。"（如跨来源，建议写为综合页）
3. "把这个成果作为资产候选。"
4. "把这个方法作为 Skill 候选。"
5. "提出一个综合页候选。"（整合 X、Y、Z 笔记）
6. "执行每周轻巡检。"
7. "执行每月深巡检。"
8. "查看待确认队列并等待我的决定。"
